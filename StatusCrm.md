Also added a client-side phone-length check (pops an alert if under 6 chars) and, while fixing Booking CRM's Loyalty view, found its "Delete" button had no backing `DELETE` route at all — disabled edit/delete there instead of adding one, since deleting a ledger entry would break the running balance chain.

**Production bug fixed (2026-08-20)**: Solo CRM's Vercel deploy (`solocrm-amber.vercel.app`) was crashing every request with `FUNCTION_INVOCATION_FAILED` / `LibsqlError: URL_INVALID: The URL 'undefined' is not in a valid format`. Root cause: `@prisma/adapter-libsql` v6's `PrismaLibSQL` is an adapter *factory* that builds its own libsql client internally from a `{url, authToken}` config — `prisma.service.ts` was instead pre-building a `@libsql/client` client and handing that object to `PrismaLibSQL`, so the factory read `.url` off a `Client` instance (undefined) and crashed on every cold start. Fixed in `solo-crm/src/prisma.service.ts` (pass the raw config directly), verified against the real production Turso DB (read + write), committed, and pushed to `main` — Vercel auto-redeployed and `solocrm-amber.vercel.app` now returns `200` consistently. Engagement CRM (`#09`, below) had copy-pasted the same bug before ever being deployed — fixed there too pre-emptively.
